# 性能：一台机器，回环 UDP

> 2026-11-04 在下面这台机器上测得。这是**基线，不是承诺**：它说明当前代码在一台主机上的代价，
> 存在的意义是让后续改动有可比较的参照。这里没有数字被外推到真实部署。

## 机器与工具链

| 项 | 值 |
|---|---|
| CPU | Apple M1 Max（10 核：8 性能核 + 2 能效核） |
| 系统 / 内核 | macOS（darwin/arm64） |
| Go | go1.27.1 |
| `GOMAXPROCS` | 默认（10） |
| 传输 | 回环 UDP（`127.0.0.1`），服务端与设备在同一进程 |
| 提交 | `14f855e` 加上 `benchmark_test.go` 里的基准 |

macOS 笔记本不是安静的机器：注册基准的轮次间波动约 ±10 %，通知基准可达 ±35 %（最短的操作
噪声最大）。第三位有效数字请当噪声看。

## 测的是什么

`benchmark_test.go` 起一个真实的 glwm2m 服务端，走回环 UDP —— 不 mock 传输层 —— 只对稳态
循环计时。建立监听、拨号、注册观察都在计时器之外。

| 基准 | 做什么 | 3 次中位数 | 折算速率 |
|---|---|---|---|
| `BenchmarkRegister` | 一次 `POST /rd?ep=…&lt=300&b=U&lwm2m=1.0`（带对象清单体），答 `2.01 Created` | 53.5 µs/op | 18.7k 次注册/秒 |
| `BenchmarkObserveNotify` | 服务端对 `/3303/0/5700` 注册 Observe；设备上报新值，服务端回调收到 | 25.8 µs/op | 38.8k 条通知/秒 |

每次操作的内存分配：

| 基准 | 字节/op | 分配次数/op |
|---|---|---|
| `BenchmarkRegister` | 72.1 kB | 133 |
| `BenchmarkObserveNotify` | 66.7 kB | 29 |

## 怎么读这些数字

- **回环上一次注册约 54 µs**：大致是一次 CoAP 往返加注册簿记 —— 解析查询串与对象清单、
  校验 lifetime 与 binding、在服务端锁下写一条 map、返回带 `Location-Path` 的 `2.01`。
  18.7k/s 远高于设备群的真实负载：1 万台、lifetime 1 小时的设备每秒只重注册约 3 次。
- **一条通知端到端约 26 µs**，从设备的 `Server.Notify` 经过下行观察到处理函数。回调跑在下行
  客户端的接收 goroutine 上，所以慢处理拖慢的是流本身，而不是把队列撑大。
- **分配没有优化过。** 每次注册约 72 kB、每条通知约 67 kB，主要来自 gnety 侧每个数据报的缓冲
  与 gcoap 侧每个交换的状态，没有任何池化。这些数字记录的是当前代价，不是目标。
- **注册基准把 `MaxRegistrations` 提到了 1<<20**：每轮都会新增一条注册，默认上限（1024）会在
  一千次之后回 `5.03`。真实服务端靠过期或替换而不是无限增长。

## 复现

```sh
cd libs/glwm2m

# 两个基准，3 次取中位数：
go test -run '^$' -bench . -benchtime=2s -count=3
```

`-run '^$'` 把单元测试挡在外面；基准从不属于 `go test ./...`，也不进 CI —— 按协议库基线，
测数字是发布期的手工动作。

## 这些数字不覆盖什么

- **真实网络。** 没有丢包、没有 RTT、没有 NAT；重传与去重由单元测试覆盖，不由这里覆盖。
- **DTLS。** 两个基准都走明文 UDP。证书 DTLS 会给每次注册加一次握手、给每个数据报加记录保护，
  两者都没有测。
- **注册过期。** 扫描是一个 goroutine，每 `ExpiryInterval`（默认 1 s）跑一次；这里不是浸泡
  测试，也没有测百万级注册对扫描的影响。
- **块传输。** 超过一个块的下行体（Block1）与被切片的响应（Block2）没有基准。
- **指标钩子与事件 sink。** 都没有挂；会分配或阻塞的钩子会改变这些数字。
- **其它硬件。** ARM64 笔记本的数字不能迁移到 ARM32 网关或服务器 CPU。
